# Demo 快速实现工作流

## 目标

用低工程成本快速产出可交互 Demo：先搭出完整体验路径，再根据演示优先级补齐关键页面的视觉和交互细节。

## P0 快速跑通

目标：让 Demo 能打开、能点击、能完整演示主流程。

必须完成：

- 建立静态项目结构：`index.html`、`styles.css`、`script.js`、`custom-assets/`。
- 搭出页面入口、主导航、核心页面、关键按钮和基础状态切换。
- 用数据常量维护卡片、列表、tab、弹窗内容，避免把内容散落在 DOM 里。
- 给关键节点加稳定 ID 或 class，方便浏览器批注和后续定位。
- 推送到 GitHub Pages，形成第一个可评审链接。

暂不做：

- 全页面像素级还原。
- 复杂动效。
- 非关键页面的完整状态。
- 生产级接口、鉴权、数据持久化。

## P1 关键路径还原

目标：把演示最常走的路径做得可信、顺滑、像真实产品。

重点还原：

- 首页第一屏、核心 CTA、输入框、推荐卡片。
- 添加/创建/选择/确认等关键流程。
- 弹窗、浮窗、toast、列表、tab、卡片选中态。
- 关键角色、头像、icon、文案和示例数据。

实现方式：

- 优先使用 Figma 导出的 SVG/PNG 作为视觉锚点。
- 对需要交互的区域使用 HTML/CSS 重建，避免整页截图不可点击。
- 对纯展示且复杂的区域，可以先用图片承载，再逐步拆成 DOM。
- 对高频复用模块抽成数据驱动渲染，例如智能体卡片、技能卡片、任务卡片。

## P2 视觉细节补齐

目标：清理演示时容易穿帮的细节。

重点处理：

- hover、active、selected、disabled、loading、empty 等状态。
- 字号、行高、颜色、间距、圆角、阴影、透明度。
- 图片尺寸、头像背景、icon 色值、按钮命中区域。
- 浮窗位置、滚动条样式、输入填充效果。
- 页面刷新后的默认入口和状态恢复。

处理顺序：

1. 先处理影响演示理解的问题。
2. 再处理高频路径视觉问题。
3. 最后处理低频页面或边缘状态。

## P3 演示稳定化

目标：保证 Demo 能在评审现场稳定打开和演示。

必须完成：

- 本地预览和 GitHub Pages 链接都可打开。
- 刷新后进入预期页面。
- 关键按钮、弹窗、浮窗、tab、输入框均可点击。
- 静态资源加版本号，避免缓存导致旧样式残留。
- 每轮提交写清楚改动范围。

## 标准交付节奏

每一轮迭代都按这个顺序：

1. 接收集中批注。
2. 归类为文案、资产、布局、交互、状态、数据。
3. 先改高优问题。
4. 本地检查。
5. 推送线上。
6. 给出变更说明和验收入口。
