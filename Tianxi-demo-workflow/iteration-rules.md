# 批注与迭代规则

## 批注格式

每条批注尽量包含：

```text
问题：当前哪里不对
期望：要改成什么
依据：设计稿链接、截图、资产文件名或具体数值
优先级：必须改 / 建议改 / 可延后
```

## 一轮反馈的范围

推荐每轮只集中处理一类问题：

- 文案和数据。
- 头像、icon、图片资产。
- 输入框、按钮、弹窗。
- tab、列表、卡片。
- hover、选中态、滚动条、toast。
- 页面默认入口和演示路径。

这样可以减少互相覆盖和返工。

## 优先级规则

必须改：

- 主流程走不通。
- 演示入口不对。
- 关键页面明显穿帮。
- 文案、角色、品牌名称错误。
- 关键按钮无法点击。

建议改：

- 关键页面间距、颜色、字号不够像。
- hover、选中态不完整。
- 资产质量不佳。

可延后：

- 低频页面细节。
- 非演示路径边缘状态。
- 不影响理解的小范围像素误差。

## 实现者处理顺序

1. 先复现问题。
2. 判断是否影响主流程。
3. 找到对应源码或资产。
4. 最小范围修改。
5. 本地检查。
6. 推送并说明变更。

## 每轮交付说明

每轮交付时说明：

- 本轮处理了哪些批注。
- 哪些问题暂未处理，原因是什么。
- 本地检查结果。
- 线上预览链接或提交 hash。

## 不推荐的反馈方式

- “整体再像一点”但不指出具体元素。
- 一条批注里混合多个页面多个问题。
- 只发截图，不说明期望改法。
- 在 P0 阶段要求所有页面像素级还原。
